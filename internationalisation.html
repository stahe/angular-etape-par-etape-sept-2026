    6. Internationalisation

    6.1. Exemple 21 : une application en deux langues

    L'application [RdvMedecins] existe en français et en anglais. Dans le cours [NestJS], c'est le serveur qui traduisait les pages, avant de les envoyer. Désormais, les pages sont fabriquées dans le navigateur : c'est donc le client qui les traduit, et changer de langue ne demande plus rien au serveur.

    [Angular] a son propre système de traduction, [@angular/localize], qui fabrique une application compilée par langue : on ne change alors de langue qu'en chargeant une autre application. Nous utiliserons plutôt la bibliothèque [ngx-translate], la plus utilisée avec [Angular], qui traduit pendant l'exécution : un clic suffit à retraduire toute la page.

    // =========================================================================
// 21-i18n/src/app/i18n/i18n.ts - la configuration de ngx-translate
// -------------------------------------------------------------------------
// ngx-translate est la bibliothèque de traduction la plus utilisée avec
// Angular. On lui fournit :
//   - un DICTIONNAIRE par langue (fr.json, en.json), où chaque texte a une
//     CLÉ ("ACCUEIL.BONJOUR") ; les paramètres s'écrivent {{nom}} ;
//   - un CHARGEUR (TranslateLoader), qui renvoie le dictionnaire d'une
//     langue. Le nôtre les prend dans le code de l'application (import de
//     fichiers JSON) ; un autre pourrait les télécharger ;
//   - la langue de départ (celle mémorisée dans localStorage, sinon celle
//     du navigateur, sinon le français) et la langue de repli.
// Dans les templates, {{ 'ACCUEIL.BONJOUR' | translate: { nom: 'Marie' } }}
// affiche le texte de la langue COURANTE ; changer de langue met toute la
// page à jour.
//
// C'est, côté client, le même principe que le cours NestJS (dictionnaires
// i18n/*.json + helper {{t}}) - mais la traduction se fait maintenant dans
// le navigateur, et changer de langue ne demande plus rien au serveur.
//
// (Angular a aussi son propre système, @angular/localize, qui fabrique UNE
// application compilée par langue : on ne peut alors changer de langue
// qu'en changeant de page. ngx-translate traduit, lui, pendant l'exécution.)
// =========================================================================

import { Provider } from '@angular/core';
import { provideTranslateLoader, provideTranslateService, TranslateLoader, TranslationObject } from '@ngx-translate/core';
import { Observable, of } from 'rxjs';
import fr from './fr.json';
import en from './en.json';

export type Langue = 'fr' | 'en';
export const LANGUES: Langue[] = ['fr', 'en'];
export const CLE_LANGUE = 'exemple21.langue';

// le chargeur des dictionnaires
class DictionnairesLoader implements TranslateLoader {
  getTranslation(langue: string): Observable<TranslationObject> {
    return of(langue === 'en' ? en : fr);
  }
}

function langueDeDepart(): Langue {
  const memorisee = localStorage.getItem(CLE_LANGUE);
  if (memorisee === 'fr' || memorisee === 'en') {
    return memorisee;
  }
  return navigator.language.startsWith('en') ? 'en' : 'fr';
}

export function provideI18n(): Provider[] {
  return provideTranslateService({
    loader: provideTranslateLoader(DictionnairesLoader),
    fallbackLang: 'fr', // une clé absente en anglais : on prend le français
    lang: langueDeDepart(),
  });
}
    • lignes 29-30 : les dictionnaires sont importés comme des modules : ils font partie du code de l'application. C'est possible grâce à l'option [resolveJsonModule] du fichier [tsconfig.json] ;
    • ligne 34 : la clé sous laquelle la langue choisie est rangée dans le [localStorage] (exemple 20) ;
    • lignes 37-41 : le chargeur des dictionnaires : [ngx-translate] l'appelle pour obtenir le dictionnaire d'une langue, sous forme d'observable. Le nôtre les prend dans le code ; un autre pourrait les télécharger depuis le serveur ;
    • lignes 43-49 : la langue de départ : celle que l'utilisateur a choisie la dernière fois, sinon celle du navigateur, sinon le français ;
    • lignes 51-57 : [provideTranslateService] rend les services de [ngx-translate] disponibles dans toute l'application. [fallbackLang] : la langue utilisée pour une clé absente du dictionnaire courant.

    // =========================================================================
// 21-i18n/src/app/i18n/pluriel.pipe.ts - choisir la forme du pluriel
// -------------------------------------------------------------------------
// ngx-translate ne gère pas les pluriels. Le dictionnaire en donne les
// formes sous une même clé ("RENDEZ_VOUS": { "zero", "one", "other" }) et
// ce pipe choisit la bonne, selon le nombre et la langue :
//     {{ 'ACCUEIL.RENDEZ_VOUS' | pluriel: n : langue | translate: { n } }}
// Intl.PluralRules connaît les règles de chaque langue ("one" ou "other" en
// français comme en anglais, mais d'autres formes en polonais, en arabe...).
// =========================================================================

import { Pipe, PipeTransform } from '@angular/core';

@Pipe({ name: 'pluriel' })
export class PlurielPipe implements PipeTransform {
  transform(cle: string, n: number, langue: string | null): string {
    if (n === 0) {
      return `${cle}.zero`;
    }
    return `${cle}.${new Intl.PluralRules(langue ?? 'fr').select(n)}`;
  }
}
    • lignes 16-21 : le pipe reçoit une clé ([ACCUEIL.RENDEZ_VOUS]), un nombre et une langue ; il rend la clé de la bonne forme ([ACCUEIL.RENDEZ_VOUS.one], par exemple) ;
    • ligne 18 : zéro a sa propre forme (« aucun rendez-vous ») ;
    • ligne 20 : [Intl.PluralRules], fourni par le navigateur, connaît les règles de chaque langue : [one] ou [other] en français et en anglais, mais d'autres formes en polonais ou en arabe. (Attention : en français, 1,5 est au singulier ; en anglais, au pluriel.)

    // =========================================================================
// 21-i18n/src/app/app.ts - une page traduite
// -------------------------------------------------------------------------
//   - 'CLE' | translate                    un texte ;
//   - 'CLE' | translate: { nom: ... }      un texte à paramètres ;
//   - date / currency avec la langue       une date, un montant, au format
//                                          de la langue courante ;
//   - translate.use('en')                  change la langue : toute la
//                                          page se retraduit.
// TranslateService.currentLang est un SIGNAL : la langue courante.
// =========================================================================

import { Component, effect, inject, signal } from '@angular/core';
import { CurrencyPipe, DatePipe } from '@angular/common';
import { TranslatePipe, TranslateService } from '@ngx-translate/core';
import { CLE_LANGUE, Langue, LANGUES } from './i18n/i18n';
import { PlurielPipe } from './i18n/pluriel.pipe';

@Component({
  selector: 'app-root',
  imports: [CurrencyPipe, DatePipe, TranslatePipe, PlurielPipe],
  templateUrl: './app.html',
})
export class App {
  private readonly translate = inject(TranslateService);
  protected readonly langue = this.translate.currentLang;
  protected readonly langues = LANGUES;
  protected readonly nombre = signal(2);
  protected readonly aujourdhui = new Date();

  // ce que renverrait le serveur RdvMedecins (cf. chapitre sur la boîte noire)
  protected readonly reponsesServeur = [
    { statusCode: 409, cle: 'ERRORS.LOGIN_TAKEN', params: {} },
    { statusCode: 429, cle: 'ERRORS.TOO_MANY_ATTEMPTS', params: { minutes: '15' } },
  ];

  // translate.translate(clé) : un SIGNAL qui suit la langue courante
  private readonly titre = this.translate.translate('APP.TITRE');

  constructor() {
    // à chaque changement de langue : on la mémorise, et on met à jour
    // l'attribut lang de la page (utile aux lecteurs d'écran, aux correcteurs)
    effect(() => {
      const langue = this.langue();
      if (langue) {
        localStorage.setItem(CLE_LANGUE, langue);
        document.documentElement.lang = langue;
      }
      document.title = String(this.titre());
    });
  }

  protected choisir(langue: Langue): void {
    this.translate.use(langue);
  }
}
    • ligne 21 : [TranslatePipe] : le pipe [translate] ;
    • ligne 25 : [TranslateService] : le service principal de [ngx-translate] ;
    • ligne 26 : [currentLang] : la langue courante, sous forme de signal ;
    • lignes 32-35 : deux réponses d'erreur, telles que les renverrait le serveur : une clé, et des paramètres ;
    • ligne 38 : [translate.translate(clé)] rend un signal qui vaut la traduction de la clé, et qui suit la langue courante ;
    • lignes 43-50 : un effet, exécuté à chaque changement de langue : la langue est mémorisée (ligne 46), l'attribut [lang] de la page est mis à jour (ligne 47 ; il sert aux lecteurs d'écran et aux correcteurs orthographiques), ainsi que le titre de l'onglet (ligne 49) ;
    • ligne 54 : [use] change la langue courante : toute la page se retraduit.

      <button class="btn btn-sm btn-outline-success" (click)="nombre.set(nombre() + 1)">{{ 'ACCUEIL.AJOUTER' | translate }}</button>

    • ligne 19 : deux pipes enchaînés : [pluriel] choisit la clé, [translate] la traduit ;
    • ligne 34 : la clé renvoyée par le serveur est traduite, avec ses paramètres.
